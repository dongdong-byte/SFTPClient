# 자료 자동 전송 프로그램 개발 성과 및 진행 현황

작성일: 2026년 9월 23일 · 두 번째 보고서  
대상: 관측자료 자동 전송 프로그램(SFTPClient)

## 1. 주요 개발 성과

**자료를 찾아 보내는 기본 기능에서 출발하여, 누락 자료 재전송, 관측소별 선택 처리, 기관별 폴더 구조 대응, 전송 이력 자동 관리, 장애 대응까지 구현 범위를 넓혔습니다.**

현재까지 개발한 내용은 다음 여섯 분야로 정리할 수 있습니다.

- **기본 전송:** 새 자료와 변경된 자료를 찾아 전송하고, 완료 여부를 확인합니다.
- **누락 자료 보완:** 과거 자료를 자동으로 다시 확인하고, 담당자가 기간을 지정해 재전송할 수 있습니다.
- **관측소 선택:** 한 곳 또는 여러 관측소의 자료만 골라 처리합니다.
- **기관별 환경 대응:** 날짜 폴더 아래의 다양한 하위 폴더에서 자료를 찾습니다.
- **기록 자동 관리:** 자료 변경 차수를 관리하고, 프로그램 개선에 필요한 기록 항목을 기존 이력 손실 없이 추가합니다.
- **운영 안정성 보강:** 실행 기록 보관, 불필요한 재전송 억제, 통신 정지 대응, 결과 요약, 미완성 파일 제외의 다섯 가지 보강을 마쳤습니다.

**화면에 드러나는 전송 기능과 함께, 중복·누락·중단 상황에서도 전송 여부를 올바르게 판단하기 위한 내부 처리와 기록 관리까지 개발했습니다.** 기능별 효과는 아래에 설명하며, 실제 절감 시간이나 전송량 감소율은 현장 측정 후 확인할 사항입니다.

현재 남은 주요 작업은 **오래된 전송 이력 자동 정리, 리눅스 환경 적용·시험, 기존 자료를 정해진 폴더로 모으기**입니다.

> 상태 기준: ‘구현 완료’는 현재 프로그램에 기능이 반영됐다는 의미입니다. 최신 기능의 기관별 현장 확인까지 모두 끝났다는 의미는 아닙니다. 아래 항목은 기존 기능과 최근 보강을 분야별로 정리한 것으로, 반복 설명되는 기능을 별도 성과로 중복 합산하지 않았습니다.

## 2. 누락 자료를 다시 보내는 기능 — 구현 완료

### 2.1 과거 자료 자동 재확인

**일반 전송을 마친 뒤, 더 오래된 기간에서 아직 보내지 못했거나 변경된 자료를 찾아 보냅니다.** 최근 자료 확인 기간을 벗어난 지연 자료도 정해진 범위 안에서 보완할 수 있게 했습니다.

추가로 반영한 내용은 다음과 같습니다.

- 새 자료 전송을 먼저 처리하고, 남은 처리 여유로 과거 자료를 확인합니다.
- 운영 시작일과 기록 보존기간을 고려해 확인 범위를 제한합니다.
- 이미 완료한 자료를 무조건 다시 보내지 않고, 기록상 처리가 필요한 자료를 고릅니다.
- 일반 전송에서 전부 실패하거나 통신이 멈춘 경우에는 후속 재전송을 진행하지 않도록 했습니다.

**기대 효과:** 담당자가 놓치기 쉬운 과거 자료를 정기 작업에서 다시 확인하고, 신규 자료 전송과 과거 자료 보완의 우선순위를 관리할 수 있습니다.

### 2.2 담당자가 기간을 지정하는 재전송

**필요한 시작일과 종료일, 자료 종류를 지정해 다시 확인하고 보낼 수 있습니다.** 장애 이후 특정 기간만 복구하거나, 별도 요청을 받은 자료를 처리하는 데 사용할 수 있습니다.

- 허용된 기간 안에서 원하는 날짜 범위를 선택합니다.
- 실제로 보내기 전에 대상 자료를 미리 확인할 수 있습니다.
- 자동 재시도 횟수를 모두 사용한 자료도 담당자가 수동으로 추가 시도할 수 있습니다.
- 다른 전송이 진행 중이면 일정 시간 기다려 작업 겹침을 줄입니다.
- 자료를 찾지 못한 경우에도 확인 결과를 남깁니다.

**기대 효과:** 담당자가 파일을 하나씩 찾아 옮기는 대신, 필요한 범위를 지정하여 복구 작업을 진행할 수 있습니다. 완료 자료 전체를 강제로 다시 보내는 기능은 아니며, 자료별 전송 기록과 설정 조건에 따라 선별합니다.

## 3. 원하는 관측소만 선택하는 기능 — 구현 완료

**재전송할 때 특정 관측소 한 곳 또는 여러 곳을 함께 선택할 수 있도록 했습니다.** 기간·자료 종류와 함께 지정할 수 있어, “두 관측소의 지난주 일별 자료만 확인” 같은 요청에 대응할 수 있습니다.

- 관측소 한 곳만 선택하거나 여러 곳을 한 번에 선택합니다.
- 영문 대소문자와 중복 입력을 정리해 같은 관측소를 일관되게 인식합니다.
- 잘못된 관측소 코드 입력은 실행 전에 확인합니다.
- 자료 이름에서 관측소를 구분하여 선택한 관측소의 자료만 처리합니다.
- 요청한 관측소별로 자료를 얼마나 찾았는지 기록합니다. 이미 전송해서 보낼 필요가 없는 경우와 자료를 찾지 못한 경우를 구분하는 데 활용할 수 있습니다.

**기대 효과:** 기관의 개별 자료 요청이나 특정 관측소의 장애 복구에 필요한 선택 처리가 가능해졌습니다.

현재 적용된 범위는 **재전송 기능**입니다. 앞으로 만들 자료 모으기 기능에도 여러 관측소 선택 요구를 반영할 예정이며, 그 부분까지 완료된 것은 아닙니다.

## 4. 기관마다 다른 폴더 구조에 대응하는 기능 — 구현 완료

**날짜 폴더 아래에 자료가 어떤 하위 폴더로 나뉘어 있는지에 관계없이, 내부 폴더를 따라 자료를 찾도록 개선했습니다.**

예를 들어 날짜 폴더에 파일이 바로 있는 경우, 시간별 폴더에 나뉜 경우, 관측소별 폴더 안에 다시 나뉜 경우를 같은 탐색 방식으로 처리합니다.

함께 반영한 세부 작업은 다음과 같습니다.

- 정해진 날짜 범위의 폴더에서만 탐색을 시작합니다.
- 하위 폴더를 일정한 순서로 확인하여 탐색 결과가 일관되도록 했습니다.
- 폴더 자체는 전송 대상에서 제외하고 일반 파일만 전달합니다.
- 다른 위치로 연결되는 항목은 건너뛰어 의도한 범위 밖으로 탐색이 이어지는 것을 줄입니다.
- 찾지 못한 폴더, 읽지 못한 폴더, 제외한 항목을 구분해 기록합니다.
- 과거의 시간별 폴더 전용 설정을 정리하고, 옛 설정이 남아 있으면 시작할 때 알리도록 했습니다.

**기대 효과:** 기관별 하위 폴더 배치 차이에 대응할 수 있는 범위가 넓어졌고, 폴더 구성에 따라 별도 처리를 추가해야 하는 부담을 줄였습니다.

날짜 폴더까지의 위치는 설정해야 합니다. 새 프로그램 적용 시 기존 경로 설정도 함께 변경해야 하며, 흩어진 자료를 새 폴더로 복사·정리하는 기능은 앞으로 개발할 별도 항목입니다.

## 5. 자료 변경과 기록 보관 방식의 자동 관리 — 구현 완료

### 5.1 같은 이름의 자료가 바뀌었을 때 변경 차수 자동 관리

**같은 파일 이름이라도 변경된 자료로 판단되면 변경 차수를 자동으로 올리고, 현재 자료를 보냈는지 다시 판단하도록 했습니다.** 이전 자료의 전송 완료 기록 때문에 수정된 자료가 빠지는 일을 방지하기 위한 기능입니다.

예를 들어 이미 보낸 자료가 나중에 수정되면, 이전 전송 완료 사실만으로 처리를 끝내지 않고 수정본의 전송 필요 여부를 판단합니다. 수정 시각만 달라지고 내용은 같다고 확인된 자료는 불필요하게 변경 차수를 올리지 않습니다.

**기대 효과:** 새 자료, 수정된 자료, 이미 보낸 자료를 구분하여 반복 전송과 수정본 누락을 함께 줄일 수 있습니다.

이는 현재 자료의 변경 차수와 전송 상태를 관리하는 기능입니다. 과거의 모든 파일 내용과 수정본을 별도로 보관하거나 되돌리는 기능은 포함하지 않습니다.

### 5.2 프로그램 개선에 맞춰 기록 항목 자동 추가

**지원하는 이전 기록 형식을 확인하여, 기존 전송 이력을 유지한 채 새 기능에 필요한 항목을 자동으로 추가하도록 했습니다.** 담당자가 설치 현장에서 기록을 지우고 다시 만들거나, 별도 변경 작업을 빠뜨리는 위험을 줄이기 위한 기능입니다.

- 프로그램 시작 시 현재 기록 형식의 버전을 확인합니다.
- 필요한 변경을 지원하는 순서에 따라 적용합니다.
- 자료 묶음 구분과 내용 비교에 필요한 기록 항목을 추가합니다.
- 적용한 기록 형식의 버전을 갱신하고 변경 결과를 실행 기록에 남깁니다.
- 한 단계의 변경이 실패하면 그 단계의 일부만 반영된 상태로 남지 않도록 처리합니다.

**기대 효과:** 기존 운영 기록을 살리면서 기능을 추가할 수 있고, 설치·교체 과정에서 담당자의 수작업을 줄일 수 있습니다. 자동 변경은 현재 프로그램에서 지원하는 이전 형식에 한해 적용됩니다.

## 6. 수정 시각 문제를 계기로 완료한 다섯 가지 운영 보강

**수정 시각만 바뀐 자료가 반복 전송될 수 있는 문제를 계기로, 원인 확인부터 전송 판단·통신 중단 대응·결과 확인까지 다섯 영역을 보강했습니다.** 다섯 항목 모두 프로그램에 반영했습니다.

### 보강 1. 실행 기록을 날짜별로 보관 — 구현 완료

실행 화면에만 남던 정보를 날짜별 파일로도 보관하도록 했습니다. 날짜가 바뀌면 새 기록 파일을 사용하고, 보존기간이 지난 기록 파일을 정리합니다. 기록 저장에 문제가 생기면 경고를 남기고 전송 작업은 계속하도록 했습니다.

**효과:** 문제가 발생한 시점의 처리 내용을 나중에 확인할 근거를 확보했습니다.

### 보강 2. 수정 시각 변경과 실제 내용 변경을 구분 — 구현 완료

파일 크기는 같고 수정 시각만 바뀐 경우, 저장한 내용 비교 정보와 현재 자료를 대조하도록 했습니다. 내용이 같은 것으로 확인되면 새 자료로 취급하지 않습니다. 비교 정보가 없거나 확인에 실패한 자료는 같은 내용이라고 단정하지 않습니다.

**효과:** 시각 정보만 바뀐 자료가 새 수정본으로 잘못 분류되어 반복 전송되는 상황을 줄이도록 했습니다.

### 보강 3. 통신이 멈춘 작업 감지와 종료 — 구현 완료·현장 확인 필요

진행 중인 전송에 설정한 시간 동안 진전이 없으면 해당 실행을 중단하도록 했습니다. 실패 기록을 남기는 절차와 다음 실행에서 중단 자료를 정리하는 절차도 연결했습니다.

**효과:** 응답 없는 통신을 계속 기다리는 상황에 대응할 수 있게 했습니다. 실제 기관 환경에서 통신을 끊고 다시 연결했을 때 종료·재실행이 정상적으로 이어지는지는 추가 확인이 필요합니다.

### 보강 4. 처리 결과와 중복 억제 현황 요약 — 구현 완료

새 자료, 변경으로 판단한 자료, 내용이 같아 변경 처리를 줄인 자료의 수와 비율을 실행 요약에 표시하도록 했습니다. 실제 전송인지 사전 확인인지, 어느 범위를 확인했는지도 함께 남깁니다.

**효과:** 개선 기능이 얼마나 적용되고 있는지 관찰하고, 이상 현상을 확인할 근거를 늘렸습니다. 이 집계는 자료 판단 결과이며, 실제 전송 성공 건수는 별도로 확인합니다.

### 보강 5. 다른 프로그램이 작성 중인 임시 파일 제외 — 구현 완료

다른 프로그램이 파일을 전달하는 중에 사용하는 임시 이름도 인식하여 전송 대상과 신규 기록 등록에서 제외하도록 보강했습니다. 정식 이름의 자료가 발견되면 기존 검사 절차에 따라 다시 판단합니다.

**효과:** 아직 전달이 끝나지 않은 자료가 완성본으로 취급되는 위험을 줄였습니다. 원본 임시 파일을 임의로 삭제하거나 이름을 바꾸지는 않습니다.

## 7. 함께 구축한 기본 전송·운영 기능

위의 최근 보강 외에도 다음 기반 기능을 구현했습니다.

- **새 자료·수정 자료 전송 — 완료:** 지정한 위치에서 자료를 찾고 기존 기록과 대조해 필요한 파일을 보냅니다.
- **늦게 도착한 자료 확인 — 완료:** 정기 실행에서 최근 날짜를 확인하고, 지정 시각에는 더 넓은 기간을 다시 확인합니다. 정기 실행은 운영체제의 예약 실행 기능과 연계합니다.
- **미완성 자료 기본 점검 — 완료:** 빈 파일이나 수정 직후 대기 시간이 필요한 자료를 바로 보내지 않습니다.
- **필요한 자료 묶음 확인 — 완료·선택 사용:** 지정한 자료 종류가 갖춰졌을 때 전송을 시작합니다. 기본적으로 꺼져 있으며 기관별 설정이 필요합니다.
- **전송 완료 확인 — 완료:** 임시 이름으로 보낸 뒤 크기를 확인하고 정식 이름으로 바꿉니다. 마지막 확인까지 통과해야 완료로 기록합니다.
- **여러 전송 작업 동시 처리 — 완료:** 동시에 처리할 작업 수와 한 번에 보낼 파일 수를 조절할 수 있습니다.
- **실패·중단 자료 재처리 — 완료:** 실패와 중단 상태를 기록하고, 다음 실행에서 범위와 횟수 조건에 맞춰 다시 시도합니다.
- **중복 실행 방지 — 완료:** 같은 기록을 사용하는 작업이 겹치지 않도록 제어합니다.
- **전송 전 미리보기 — 완료:** 실제로 보내기 전에 대상과 처리 범위를 확인할 수 있습니다.
- **최초 설치 시 기존 전송분 반영 — 완료:** 서버에 이미 있는 자료의 크기를 대조해 기존 전송분을 기록에 반영할 수 있습니다.
- **접속 정보 보호 — 윈도우 구현 완료:** 서버 주소와 접속 계정 등의 설정값을 암호화하여 저장하고 사용할 수 있습니다.
- **잘못된 설정과 접속 대상 확인 — 완료:** 시작 전에 설정을 검사하고, 접속 시 등록된 상대 서버인지 확인합니다.

## 8. 앞으로 완료할 주요 작업

### 8.1 오래된 전송 이력 자동 정리 — 미구현·우선 진행

30일 보존 설정을 실제 전송 이력 정리로 연결해야 합니다. 정리 이후 오래된 파일이 새 자료로 오인되어 다시 전송되지 않는지도 확인해야 합니다. 완료된 ‘날짜별 실행 기록 파일 정리’와는 별개이며, 원본 관측자료를 삭제하는 작업은 아닙니다.

### 8.2 리눅스 환경 적용·시험 — 미완료

리눅스용 실행파일 준비, 실제 자료 경로, 예약 실행, 서버 연결과 전체 전송 과정을 확인해야 합니다. 현재 구현된 기능과 별도로 운영환경에 맞춘 적용 작업이 남아 있습니다.

### 8.3 기존 자료를 정해진 폴더로 모으기 — 미구현

기관마다 다른 저장 위치에서 자료를 찾아, 파일명에 적힌 관측 날짜에 맞춰 정해진 폴더로 복사하는 기능입니다. 여러 관측소 선택, 복사 완료 확인, 처리 이력 관리까지 구현할 예정입니다. 이후 기존 전송 기능이 정리된 폴더의 자료를 보내도록 구성합니다.

이번 단계는 프로그램이 접근할 수 있는 기존 저장 위치의 자료를 모으는 범위입니다. 다른 서버에 접속해 내려받는 기능과 수신·송신 통합은 후속 단계로 구분합니다.

## 9. 현장 확인 및 범위 구분

최신 프로그램 적용 후에는 기관별로 **실제 폴더의 자료 탐색, 통신 장애 후 종료·재시도, 기존 이력 유지, 실행 기록 보관, 자료량에 맞는 처리 시간**을 확인해야 합니다.

관측자료의 내용 자체에 대한 품질 검사, 과거 수정본 전체 보관·복원, 중단 지점부터 이어 보내기, 자료 묶음 전체의 전송 취소·되돌리기는 현재 완료 범위에 포함하지 않습니다. 미완성 자료 묶음의 별도 보고서 발송은 이번 개발 범위에서 제외했으며, 리눅스 전용 추가 보안은 공식 점검 요구가 있을 때 별도로 검토합니다.
