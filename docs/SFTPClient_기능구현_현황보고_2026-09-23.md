# 자료 자동 전송 프로그램 기능 구현 현황

작성일: 2026년 9월 23일  
대상: SFTPClient — 관측자료를 찾아 지정된 서버로 보내는 프로그램

## 1. 현재 진행 상황

**자료를 찾아 보내고, 전송 결과를 기록하며, 빠진 자료를 다시 보내는 기본 기능은 구현했습니다.** 최근에는 내용이 같은 자료의 불필요한 재전송을 줄이고, 통신이 멈췄을 때 작업을 종료하며, 기관마다 다른 하위 폴더에서 자료를 찾는 기능까지 보강했습니다.

**앞으로 남은 주요 작업은 오래된 전송 이력 자동 정리, 리눅스 환경 적용·시험, 기존 자료를 정해진 폴더로 모으는 기능입니다.** 따라서 전체 개발이 완료된 상태는 아닙니다.

이 문서의 상태는 다음 의미로 사용합니다.

- **구현 완료:** 현재 프로그램에 기능이 반영되어 있습니다. 모든 기관에서 최신 기능의 현장 확인까지 끝났다는 뜻은 아닙니다.
- **미구현:** 요구사항이나 설계는 있으나, 실제로 사용할 기능은 아직 만들어야 합니다.
- **현장 확인 필요:** 기능은 있으나, 실제 설치 환경에서 동작과 운영 설정을 추가로 확인해야 합니다.
- **후속 검토·이번 범위 제외:** 현재 개발할 항목과 구분하여 관리하는 사항입니다.

## 2. 구현한 기능

### 2.1 자료 찾기와 전송

**① 새 자료와 변경된 자료 찾아 보내기 — 구현 완료**

지정한 폴더에서 자료를 찾고, 이전 전송 기록과 비교해 새로 들어왔거나 변경된 자료를 서버로 보냅니다. 이미 전송을 마쳤고 변경되지 않은 자료는 반복해서 보내지 않습니다. 날짜별·시간별 자료와 관측자료 형식별로 전송 대상을 설정할 수 있습니다.

**② 늦게 들어온 자료 다시 확인하기 — 구현 완료**

정기 실행 시 최근 날짜의 자료를 확인하고, 지정한 시각에는 더 넓은 기간을 다시 살펴봅니다. 제때 도착하지 않은 자료가 나중에 들어와도 설정한 기간 안에서 찾아 보낼 수 있습니다. 정기 실행 시각은 운영체제의 예약 실행 기능으로 관리합니다.

**③ 기관마다 다른 하위 폴더에서 자료 찾기 — 구현 완료**

날짜 폴더 아래에 자료가 바로 있거나, 시간별·관측소별 폴더 등으로 나뉘어 있어도 하위 폴더를 따라 내려가 자료를 찾습니다. 기관별 폴더 배치 차이에 대응하기 위한 기능입니다. 단, 날짜 폴더까지의 위치는 설정해야 하며, 아무 위치에 있는 자료를 자동으로 날짜별 정리하는 기능은 별도 개발 대상입니다.

**④ 여러 전송 작업을 함께 처리하기 — 구현 완료**

여러 폴더의 전송 작업을 설정한 개수까지 동시에 처리합니다. 한 번에 처리할 파일 수와 동시 작업 수를 제한할 수 있어 자료가 많이 쌓였을 때 전송량을 조절할 수 있습니다. 실제 처리 속도는 회선과 상대 서버 환경에 따라 달라집니다.

### 2.2 중복 전송과 불완전한 자료 줄이기

**⑤ 내용이 그대로인 자료의 불필요한 재전송 줄이기 — 구현 완료**

파일 크기는 같고 수정 시각만 바뀐 경우, 저장해 둔 내용 비교 정보와 대조합니다. 내용까지 같다는 것이 확인되면 새 자료로 취급하지 않습니다. 비교할 정보가 없거나 확인에 실패한 경우까지 같은 자료로 단정하지는 않습니다.

**⑥ 아직 만들어지는 중인 자료 제외하기 — 구현 완료**

임시 이름으로 저장 중인 파일, 내용이 비어 있는 파일, 수정 직후라 대기 시간이 필요한 파일은 바로 보내지 않습니다. 자료가 완성된 뒤 다음 확인에서 다시 판단합니다. 이는 전송 전 기본 점검이며, 관측값 자체의 품질을 검사하는 기능은 아닙니다.

**⑦ 필요한 자료가 한 묶음으로 갖춰졌을 때 전송 시작하기 — 구현 완료·선택 사용**

함께 필요한 자료 종류를 정해 두면, 해당 묶음이 갖춰졌을 때 전송을 시작할 수 있습니다. 기본적으로는 꺼져 있으며, 사용하는 기관에 맞게 설정해야 합니다. 전송 도중 일부 파일이 실패했을 때 이미 보낸 파일까지 되돌리는 기능은 포함하지 않습니다.

**⑧ 전송 중인 파일과 전송을 마친 파일 구분하기 — 구현 완료**

서버에 보내는 동안에는 임시 이름을 사용하고, 파일 크기를 확인한 후 정식 이름으로 바꿉니다. 마지막 크기 확인까지 통과해야 전송 완료로 기록합니다. 상대 서버에 저장된 파일의 내용을 모두 다시 읽어 원본과 비교하는 방식은 아닙니다.

### 2.3 누락·실패 자료 처리

**⑨ 최근 확인 기간보다 오래된 자료 자동 재확인 — 구현 완료**

일반 전송을 먼저 처리한 뒤, 정해진 과거 기간에서 아직 보내지 못했거나 변경된 자료를 추가로 찾습니다. 운영 시작일과 보존기간을 고려해 범위를 제한하며, 일반 전송에서 남은 처리 여유 안에서 진행합니다. 이미 전송이 끝난 자료를 일괄해서 다시 보내는 기능은 아닙니다.

**⑩ 기간·관측소를 지정해 다시 보내기 — 구현 완료**

담당자가 날짜, 관측소, 자료 종류를 지정하여 필요한 자료를 다시 확인하고 보낼 수 있습니다. 여러 관측소를 한 번에 선택할 수 있고, 자동 재시도 횟수를 모두 사용한 자료에도 수동 실행으로 추가 시도 기회를 줄 수 있습니다. 요청할 수 있는 기간에는 제한이 있으며, 다시 보낼 때 필요한 자료 종류 조건도 설정에 따릅니다.

**⑪ 전송 실패·프로그램 중단 후 다시 처리하기 — 구현 완료**

실패한 자료와 진행 중이던 자료의 상태를 기록하고, 다음 실행에서 정리한 뒤 조건에 맞는 자료를 다시 시도합니다. 반복 실패가 끝없이 계속되지 않도록 횟수를 제한합니다. 중간에 끊긴 파일의 나머지 부분만 이어 보내는 방식은 아닙니다.

**⑫ 통신이 멈춘 작업 감지하기 — 구현 완료·현장 확인 필요**

전송 작업에 일정 시간 동안 진전이 없으면 해당 실행을 중단하고 실패 상태를 남기도록 했습니다. 통신 회복 후에는 다음 실행에서 재시도 조건에 따라 처리합니다. 실제 기관 환경에서 통신을 끊었을 때 종료와 다음 실행이 정상적으로 이어지는지는 추가 확인이 필요합니다.

### 2.4 운영과 관리

**⑬ 실행 결과 남기기 — 구현 완료**

찾은 자료 수, 보낸 자료 수, 실패·제외 사유 등을 실행 기록으로 남깁니다. 날짜별 기록 파일을 보관하고 보존기간이 지난 기록 파일을 정리합니다. 내용이 같아서 불필요한 재전송을 줄인 건수와 비율도 확인할 수 있습니다.

**⑭ 작업이 겹쳐 실행되는 것 방지하기 — 구현 완료**

같은 전송 이력을 사용하는 작업이 겹치지 않도록 실행을 제한합니다. 수동 재전송은 기존 작업이 끝나기를 일정 시간 기다릴 수 있습니다. 실제 최장 실행 시간에 맞는 대기·제한 시간 설정이 필요합니다.

**⑮ 실제 전송 전 대상 미리 확인하기 — 구현 완료**

파일을 실제로 보내지 않고 어떤 자료가 전송 대상이 되는지 확인할 수 있습니다. 전송 대상 선정에 따른 이력 등록·변경도 하지 않아 설정과 재전송 범위를 사전에 점검하는 데 사용할 수 있습니다.

**⑯ 최초 설치 시 이미 보낸 자료 반영하기 — 구현 완료**

서버에 이미 있는 자료와 원본의 파일 크기를 대조하여 기존 전송분을 기록에 반영할 수 있습니다. 새 프로그램 설치 직후 같은 자료가 대량으로 다시 전송되는 것을 줄이기 위한 기능입니다. 파일 크기가 같다는 기준을 사용하므로 내용 전체가 동일하다는 확인과는 구분합니다.

**⑰ 접속 정보 보호와 잘못된 설정 확인 — 구현 완료**

윈도우 환경에서 서버 주소·접속 계정 등의 설정값을 암호화해 저장하고 읽는 기능을 구현했습니다. 서버 접속 시 등록된 상대 서버인지 확인하며, 잘못된 설정은 시작 단계에서 알립니다. 리눅스에 동일한 설정값 보호 기능을 구현한 상태는 아닙니다.

**⑱ 기능 추가 시 기존 전송 이력 유지 — 구현 완료**

최근 기능 보강에 필요한 기록 항목을 추가할 때 기존 전송 이력을 유지하면서 갱신하도록 했습니다. 기능을 추가했다는 이유로 기존 기록을 지우고 처음부터 전송하지 않도록 하기 위한 기능입니다.

## 3. 앞으로 구현해야 할 주요 기능

### 3.1 오래된 전송 이력 자동 정리 — 미구현·우선 진행

현재 30일 보존 설정은 있지만, 기간이 지난 전송 이력을 실제로 정리하는 기능은 아직 없습니다. 이를 구현하고, 기록을 정리한 뒤 오래된 자료가 새 자료로 오인되어 다시 전송되지 않는지도 확인해야 합니다.

앞서 완료한 **실행 기록 파일의 정리**와 이번에 남은 **파일별 전송 이력의 정리**는 서로 다른 기능입니다. 원본 관측자료를 삭제하는 기능을 뜻하지 않습니다.

### 3.2 리눅스 환경 적용과 시험 — 미완료

리눅스용 실행파일 준비, 실제 자료 경로 설정, 예약 실행, 서버 연결, 전체 전송 과정을 확인해야 합니다. 윈도우에서 기능이 구현됐다는 것과 리눅스 운영 준비가 끝났다는 것은 구분해야 합니다.

### 3.3 기존 자료를 정해진 폴더로 모으기 — 미구현

기관마다 다른 위치에 저장된 자료를 찾아, 파일명에 적힌 관측 날짜를 기준으로 정해진 폴더에 복사하는 기능입니다. 이후 기존 전송 기능이 이 폴더의 자료를 보내도록 구성할 예정입니다.

2026년 9월 20일 요구사항에 따라 이번 개발 범위에 포함됐습니다. 관측소 여러 곳을 선택하는 요구도 반영해야 하며, 날짜 판별·복사 완료 확인·처리 이력 관리 등의 세부 설계를 확정하고 구현해야 합니다. 여기서 말하는 자료 수집은 **프로그램이 접근할 수 있는 기존 저장 위치에서 자료를 복사하는 것**입니다. 다른 서버에 접속하여 내려받는 기능은 후속 단계입니다.

## 4. 구현한 기능 중 현장에서 추가로 확인할 사항

- **통신 장애 후 정상 복구:** 실제 통신 중단 상황에서 작업이 종료되고, 다음 실행에서 필요한 자료가 다시 처리되는지 확인합니다.
- **최신 폴더 탐색 방식 적용:** 기관별 실제 폴더에서 자료를 빠뜨리지 않는지 확인합니다. 최신 프로그램 적용 시 옛 경로 설정도 함께 변경해야 합니다.
- **기존 기록 유지와 실행 기록 보관:** 프로그램 교체 후에도 기존 전송 이력이 보존되고, 실행 기록이 정상적으로 생성·정리되는지 확인합니다.
- **재전송 범위와 처리 시간:** 실제 자료량에서 일반 전송과 과거 자료 재확인이 정해진 실행 간격 안에 끝나는지 확인합니다.

위 항목은 신규 기능 개발과 구분되는 현장 확인 사항입니다. 이번 보고서 작성 과정에서 기관 서버에 접속하거나 장애 시험을 새로 수행하지 않았습니다.

## 5. 후속 검토 또는 이번 개발 범위에서 제외한 사항

- **다른 서버에서 자료 내려받기·수신과 송신 통합:** 기존 저장 자료를 모으는 기능 이후 단계입니다. 현재 프로그램에서는 내려받기와 수신·송신 통합 실행을 지원하지 않습니다.
- **미완성 자료 묶음의 별도 보고서 발송:** 현재 결정상 이번 개발 범위에서 제외했습니다. 남은 필수 개발 항목으로 계산하지 않습니다.
- **리눅스 전용 추가 보안 기능:** 공식 보안점검에서 구체적인 요구가 나오면 별도로 검토합니다.
