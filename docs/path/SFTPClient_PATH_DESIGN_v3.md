## 개정 이력

### v2 → v3 (코드 대조 검토 반영)

| # | 항목 | v2 | v3 |
|---|---|---|---|
| 1 | 동일 이름 중복 수집(§3) | `[SCAN][WARN]` 경고 신설 제안 | **신설하지 않는다.** 기존 put 중복 가드(`runner.go` `seen`)를 그대로 쓰고, **순회 순서 규약**만 정한다 |
| 2 | 하위 폴더 항목 | 언급 없음 | 재귀로 내려간 폴더는 **Entry로 넘기지 않는다.** 넘기면 put이 매 회차 `dir=` 거부로 센다(§4) |
| 3 | symlink / junction | "따라가지 않는다" [제안] | **"따라가지도 않고, 파일로도 취급하지 않는다. 일반 파일·폴더가 아니면 건너뛰고 집계한다"** [확정]. 방어 계층과 알려진 한계(bind mount) 명시(§5) |
| 4 | §1.1 "시각 값을 아무 데도 쓰지 않는다" | 단정 | **정정.** `When`은 후보 정렬에도 쓰인다. 하루 안 정렬이 시각순 → 이름순으로 바뀐다(§1.2) |
| 5 | 개정 대상 | 테스트 일부 누락 | (HH)·HourLayout 의존 테스트 파일 추가, `local.go` 계약 주석 추가(§8) |

**코드로 확인된 v2 주장 (변경 없음)**

- 이건 config에 대한 항목이다 
- 남은 `HourLayout` 줄은 `load.go` `knownKeys`에서 키를 빼는 것만으로 `ErrUnknownKey`로
  시작이 거부된다. 거부 코드를 새로 만들 필요가 없다.
- 실제 하위 시각 폴더의 이름과 존재 여부는 해석하지 않는다. 단, 설정 템플릿의 옛 (HH) 토큰은 제거됐으므로 남아 있으면 시작 단계에서 거부한다.

## 0. 한 줄 요약

`LocalPath`는 날짜 폴더(`...\(YYYY)\(DOY)\`)까지만 적고, **그 아래는 무엇이 있든
전부 재귀로 스캔**한다. 단 **진짜 폴더만 내려가고, 일반 파일만 수집**한다.
(HH) 토큰과 `HourLayout`은 코드에서 **삭제**한다.
날짜·창·장부·resend의 판정 규칙은 바뀌지 않는다. 단, 같은 날짜 안의 후보 정렬과
scan 나열 집계의 의미는 §1.2와 §5.4처럼 달라진다.

```
LocalPath = D:\RINEX2\(YYYY)\(DOY)\        ← 템플릿 전개는 기존 그대로
                          │
                          └─ 재귀 (깊이 무제한. HH 폴더든 다른 폴더든 상관 않음)
                               · 진짜 폴더만 내려간다   (링크는 따라가지 않음)
                               · 일반 파일만 수집한다   (그 외는 건너뛰고 내부 집계)
```

## 1. 확정 사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | LocalPath | `(YYYY)\(DOY)\`까지 적는다. 전개된 날짜 디렉터리 **아래 전체를 재귀 수집**한다. [확정] |
| 2 | 재귀 깊이 | **제한 없음.** 날짜 폴더가 이미 범위를 제한하므로 깊이 제한은 존재하지 않는 문제에 대한 방어다. 날짜 폴더 밖으로 새지 않는 것은 #8이 보장한다. [확정] |
| 3 | (HH) 토큰 | pathpl에서 **지원 코드를 삭제**한다. 거부 검증을 새로 만들지 않는다 — pathpl은 모르는 토큰을 로드 단계에서 오류로 내므로, 기존 장치가 거부를 공짜로 대신한다. LocalPath·RemotePath 모두 해당. [확정] |

### 1.1 왜 재귀가 (HH)를 대체할 수 있는가

- (HH) 물리 배치는 Category(주기)와 독립된 축이다(hourlayout.go 주석). 파일의
  실제 시각은 파일명(세션 문자 `a~x`, RINEX3/4 `YYYYDDDHHMM`)에 인코딩되어 있어
  디렉터리에서 시각을 얻을 필요가 없다.
- 표준 흐름의 RemotePath는 버전별 고정 평면이라 (HH)를 채울 곳이 없고, 창 필터는
  날짜 단위다.
- 따라서 "HH 폴더가 있는가"는 해석할 규칙이 아니라 **무시할 차이**다. 재귀가
  무시를 구현한다.

### 1.2 `When`의 변화와 정렬 부작용

v2는 "이 프로그램은 시각 값을 아무 데도 쓰지 않는다"고 적었으나 정확하지 않다.
`Batch.When` → `Candidate.When`은 두 곳에서 쓰인다.

| 사용처 | 변경 전 | 변경 후 |
|---|---|---|
| `RemotePath.Expand(c.When)` (`transfer.go:389`) | (HH) 전개에 시각 사용 | (HH) 토큰이 없으므로 날짜만 쓴다. 영향 없음 |
| `SortCandidates` (`plan.go:174`, `When → file_name → category`) | Hourly dir 배치는 시각순 | `When`이 항상 그날 00:00이므로 **하루 안에서는 이름순(관측소순)** |

- 날짜 단위로는 여전히 오래된 것부터 배출하므로 "밀린 데이터를 오래된 것부터"라는
  정렬 목적은 유지된다.
- 달라지는 것은 `MaxFilesPerRun` 절단 시 **같은 날짜 안에서** 어느 파일이 다음 회차로
  밀리는지뿐이다. 해롭지 않다고 판단하며, 동작 변경으로 기록만 한다. [확정]
- 파일명 시각을 `When`에 넣는 안은 채택하지 않는다 — §2-B(관측일 파일명 추출 연기)와
  같은 이유로 PUT에 파일명 시각 파서를 들이지 않는다.

### 1.3 RemotePath에 (HH)가 있으면

(HH) 지원 코드가 삭제되므로 pathpl이 "알 수 없는 토큰"으로 로드를 거부한다.
논리적으로도 옳다 — 시각 폴더 정보를 더 이상 쓰지 않으므로 (HH)를 채우면
24시간치가 한 폴더에 몰리는 조용한 오동작이 된다. 조용히 틀리는 대신 시작에서
시끄럽게 선다.

- **[제안, 미채택 시 무해]** (HH)와 `HourLayout`에 한해 일반 "알 수 없는 토큰/키"
  오류 대신 특례 메시지를 낸다: *"(HH)는 제거된 토큰입니다. LocalPath를
  (DOY)까지로 줄이면 그 아래는 자동으로 탐색합니다."* 폐쇄망 현장에서 문서 없이
  고칠 수 있게 하는 목적이며, 지원 코드를 되살리는 것이 아니라 이름만 오류
  안내용으로 남기는 것이다.

## 3. 동일 이름 중복 수집 — 기존 가드 재사용 + 순회 순서 규약

재귀는 평면 파일과 HH 폴더 안 파일을 **같은 file_name으로 동시에** 주울 수 있다
(전환기 잔재 등). 기존 (HH) 계산 방식에서는 구조적으로 드물던 경우다.

### 3.1 이미 있는 장치 [확정]

`internal/put/runner.go` `visitBatch`는 카테고리 실행 단위로 정규화 이름 집합
`seen`을 유지한다(`runner.go:591`).

- 먼저 나온 파일이 이긴다. 나중 것은 장부 조회·Upsert 전에 빠진다.
- 로그 `[PUT][WARN] category=… duplicate normalized name=… source=…`,
  집계 `SkippedDuplicate`.
- 둘째 파일은 장부에 오르지 않으므로 **size가 달라도 revision 루프가 생기지 않는다.**
  (두 파일이 번갈아 common을 갱신하는 경로가 없다.)

재귀 Batch도 같은 `visitBatch`를 지나므로 **새 코드가 필요 없다.**

### 3.2 남는 일 — "누가 먼저인가"를 결정적으로 [확정]

먼저 나온 쪽이 이기므로 순회 순서가 곧 규칙이다. 실행마다 달라지면 안 된다.

- **현재 폴더의 파일을 먼저 Batch로 넘기고, 그다음 하위 폴더를 이름 오름차순으로
  내려간다.** (`os.ReadDir`는 이름순 정렬을 보장한다.)
- 결과: 날짜 폴더 바로 아래의 **평면 파일이 HH 폴더 안 사본보다 이긴다.**
- 처리 규칙(둘 다 보류 등, v1 Q9)은 DOWNLOAD의 동일 쟁점과 함께 결정한다. [연기]

## 4. 하위 폴더 항목 — Batch에서 제외

### 4.1 문제

현재 계약은 "scan은 하위 디렉터리도 관측한 그대로 Entry로 넘긴다"이다
(`internal/scan/local.go` `List` 주석). put은 그 항목을 Verifier에 넘겨
`dir=` 거부와 `SkippedDirs`로 센다(`runner.go:522`).

재귀를 넣은 뒤에도 폴더를 넘기면, 서울시 형태에서는 매 회차 **날짜당 24건씩
"거부"가 쌓이는 잡음**이 생긴다. 운영자가 보는 거부 집계가 의미를 잃는다.

### 4.2 결정 [확정]

- **scan이 재귀로 소비한 폴더는 Batch Entry로 넘기지 않는다.** 폴더는 탐색 대상이지
  전송 후보가 아니다.
- `LocalLister.List` 자체는 지금처럼 폴더를 포함해 돌려준다(나열의 사실).
  걸러내는 곳은 재귀를 수행하는 `Scanner`다.
- put의 `IsDir` 방어 분기와 `SkippedDirs`는 남긴다. 정상 경로에서는 0이 되고,
  0이 아니면 scan 계약 위반 신호다.
- `local.go`·`scan.go`의 계약 주석을 이에 맞게 고친다(§8).

## 5. 링크·비정규 항목

### 5.1 규칙 [확정]

> **따라가지도 않고, 파일로도 취급하지 않는다.
> 일반 파일·진짜 폴더가 아니면 건너뛰고 내부 집계한다.**

| 부분 | 막는 것 |
|---|---|
| **따라가지 않는다** | 날짜 폴더 안의 링크가 보관 루트를 가리키면 10년치를 스캔해 장부에 없는 옛 파일을 대량 재전송한다. 상위 폴더를 가리키면 무한 반복이다. |
| **파일로도 취급하지 않는다** | `os.ReadDir`는 링크를 **링크 자체**로 보고한다(`IsDir=false`, 크기는 링크 크기). 폴더를 가리키는 링크는 "파일"로 장부에 올라 전송 시 열기 실패, 파일을 가리키는 링크는 장부의 링크 크기와 실제 업로드 크기가 달라 Size 검증 실패 — 어느 쪽이든 **절대 성공하지 못하는 전송을 매시간 시도**한다. |
| **건너뛰고 내부 집계한다** | 말없이 빼면 누락이 된다. 정상 실행의 CMD 출력은 늘리지 않고, 실제 발생 시에만 기존 경고 체계로 알린다. |

Windows junction도 같은 규칙을 따른다(Go 1.23 이후 mount point는
`ModeSymlink`가 아니라 `ModeIrregular`로 보고되며, 일반 파일·폴더가 아니므로
건너뛰는 쪽에 들어간다).

### 5.2 방어 계층

| 계층 | 막는 것 | 비용 |
|---|---|---|
| ① **진짜 폴더만 내려간다** | 날짜 폴더 밖으로 새는 것, 무한 반복 | 0 — `os.ReadDir`의 `IsDir()`는 링크에 대해 false다. "IsDir이면 내려간다" 조건 자체가 링크를 따라가지 않는다 |
| ② **일반 파일이 아니면 건너뛰고 집계** | 링크를 파일로 착각해 매시간 FAILED 반복 | 조건 한 줄 + `scan.Entry`에 항목 종류 필드 하나 |
| ③ `MaxFilesPerRun` (기존) | 만에 하나 대량 오판 시 한 회차 피해 상한 | 0 — 이미 있음 |

①이 **"날짜 폴더가 범위를 막는다"(§1-2, §2-D)는 전제를 구조적으로 보장**한다.
재귀가 내려가는 모든 폴더는 물리적으로 날짜 폴더의 자식이다.

### 5.3 예외와 한계

- **루트 자체가 링크인 것은 정상 동작한다.** GNSS 통합서버 이력(2017-07-05)처럼
  디스크 부족으로 VHD를 붙이고 `mklink`로 기존 경로에 연결한 구성이 실제로 있다.
  설정에 적힌 경로(LocalPath 전개 결과)는 직접 열므로 OS가 링크를 따라간다.
  §5.1 규칙은 **재귀 도중 안에서 발견한 항목**에만 적용한다.
- **알려진 한계 — Linux bind mount.** `mount --bind`는 링크가 아니라 진짜 폴더로
  보여 ①을 통과한다. 날짜 폴더 안 bind mount는 RINEX 저장소에서 사실상 쓰이지
  않으므로 대응하지 않는다(§2-K). [연기]

### 5.4 집계와 출력 규칙 [확정]

- `scan.Entry`에 항목 종류를 담는다(예: `DirEntry.Type()` 기반 `Regular bool`
  또는 `fs.FileMode` 타입 비트). `LocalLister`가 채운다.
- 판정과 집계는 재귀를 수행하는 `Scanner`가 한다.
- `scan.Result.Files`는 **재귀 탐색 중 발견하여 Batch로 전달한 일반 파일 수**다.
  재귀로 소비한 디렉터리와 링크·junction 등 비정규 항목은 포함하지 않는다.
  `.part`·`.filepart`는 일반 파일이므로 Files에는 포함하고, 이후 기존 Verifier가
  `SkippedPart`로 제외한다.
- 비정규 항목 건수는 내부 집계한다. 0이면 CMD에 새 필드를 출력하지 않는다.
  1건 이상일 때만 기존 `[SCAN][WARN]` 체계로 Category별 요약 한 줄을 남기고,
  상세 경로가 필요하면 기존 Failure 상세 상한과 같은 방식으로 제한한다.
- 정상 실행의 기존 scan 요약 줄에는 새 출력 필드를 추가하지 않는다. `listed=`는
  위에서 확정한 `scan.Result.Files`, 즉 Batch로 전달한 일반 파일 수를 뜻한다.
- 이름 표기는 구현 시 메시지 문서(MESSAGES_AND_EXIT_CODES)의 기존 집계 표기에
  맞춘다.

## 7. 배포 주의 — 실행파일과 config는 함께 간다

새 바이너리 + 옛 config(= (HH) 또는 HourLayout 잔존)는 시작이 거부된다.
조용한 오동작이 아니라 안전한 실패지만, 현장이 서는 것은 같다.

| 설치처 | 확인 항목 |
|---|---|
| 서울시 | LocalPath에 (HH) **있음**. 재배포 시 「바이너리 + config 동시 교체, LocalPath에서 `(HH)\` 제거」를 절차에 포함한다. RemotePath는 확인된 실제 값 `/RNX2/`를 유지한다. |
| 지리원 · 측위원 · 천문연(Linux) | config 실물에서 (HH)·HourLayout 부재 확인 후 배포. |

내일(9/23)은 테스트라 운영 설치처에 영향이 없다. 위 표는 다음 재배포 시점의
체크리스트다.

### 7.1 내일 테스트 시나리오 (Windows, `Transport = localfs`)

| # | 시나리오 | 기대 |
|---|---|---|
| T1 | 서울시형 원본 `\(YYYY)\(DOY)\(HH)\` | 24개 HH 폴더의 파일 전부 수집, `dir=` 거부 0 |
| T2 | 지리원형 원본 `\(YYYY)\(DOY)\` 평면 | 기존과 동일하게 수집 |

자동 테스트는 생성 실패 시 `t.Skip` 한다.
