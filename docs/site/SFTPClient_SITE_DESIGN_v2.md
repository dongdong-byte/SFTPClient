## 1. 목적과 확정 범위

대표가 특정 관측소만 다운로드하는 인자를 제안했고, 관측소 선택은 resend에도
필요하다. 따라서 `--site`를 추가하고 공통 규칙을 이 문서에서 관리한다 **[확정]**.
과거 관측소 필터 보류 판단은 이번 운영 요구로 변경한다.

- resend에서 `--site`와 `--category`를 함께 사용할 수 있다 **[확정]**.
- 사용 예시는 `site → category → from → to` 순서로 작성한다 **[확정]**.
- **복수 site 선택은 resend뿐 아니라 향후 DOWNLOAD에서도 지원한다 [확정].**
  `--site DBON,SONP`처럼 한 요청에 여러 관측소를 지정하고, 지정한 관측소 중
  하나에 일치하는 자료를 선택한다. 입력 정규화·추출·매칭 규칙은 공통으로 사용한다.
- DOWNLOAD 구현은 MVP3 범위다. 복수 site 지원 요구의 확정과 다운로드 기능의
  구현 완료는 별개다. 일반 자동 PUT의 site 인자 지원은 이번에 확정하지 않는다.

```text
rinexclient resend --site DBON --category RINEX2_DAILY --from 2026-09-01 --to 2026-09-03
```

카테고리 값과 `--from` 사이에는 공백이 필요하다. 표기 순서는 예시의 관례이며
옵션 순서 자체를 파서에서 강제하지 않는 것을 제안한다.

## 2. 선택 조건의 역할 [제안]

- site는 관측소, category는 RINEX 버전·시간/일 구분, 날짜는 관측 기간을 선택한다.
- 함께 지정한 조건은 교집합이다. site가 category를 대체하지 않는다.
- `--site` 생략 시 모든 관측소, `--category` 생략 시 해당 명령의 활성 카테고리다.
- site 선택은 성공 파일 강제 재전송, 게이트 정책, 재시도 예산 변경을 뜻하지 않는다.

## 3. 입력과 매칭

### 3.1 CLI 입력 **[확정]**

운영자가 넣는 값은 **4자리 관측소 코드가 정석**이다. RINEX3·4 파일명에 있는
9자리 식별자는 파일에서 추출하는 재료일 뿐, `--site` 입력 형식이 아니다.

- 이름은 `--site`로 통일한다. `--station` 별칭은 추가하지 않는다.
- 하나 또는 쉼표로 구분한 여러 값을 허용한다: `--site DBON,SONP`.
- 영문 대소문자를 구분하지 않고 공백 제거·대문자 정규화 후 중복을 제거한다.
- 각 값은 ASCII 영숫자 **정확히 4자리**만 허용한다 (`[A-Za-z0-9]{4}`).
  와일드카드·정규식·9자리·그 외 길이는 실행 전 오류다.
- 네 자리를 영문만으로 강제하지 않는다. 어떤 관측소는 **네 번째가 숫자**다
  (예: `SUW1`). 앞 세 자리가 숫자인 경우까지 현장에서 확인된 것은 아니나,
  입력 문법은 네 자리 모두 영숫자를 받도록 둔다. 하이픈·한글·공백 포함은 거부한다.
- 빈 값, 빈 목록 요소는 실행 전 오류다. `--site` 생략과 명시적인 빈 값은 다르다.

### 3.2 파일명의 관측소 식별 **[제안]**

현재 코드는 RINEX2 짧은 파일명과 RINEX3·4 긴 파일명의 구조를 구분한다.
새 함수는 기존 파일명 파싱을 검토·재사용하며, 임의 파일명의 앞 글자만 잘라
유효한 관측소로 인정하지 않는다. 정확한 함수명과 배치는 구현 전에 정한다.

- RINEX2: 유효한 짧은 파일명에서 **4자리** 관측소 코드를 추출한다.
- RINEX3·4: 유효한 긴 파일명의 첫 필드(9자리)에서 **앞 4자리**를 관측소 코드로 쓴다.
  9자리 전체를 `--site`와 대조하지 않는다.
- 폴더명으로 관측소를 추정하지 않는다. 경로 범용화 이후에도 같은 규칙을 사용한다.
- 이 검사는 관측소 등록부 조회나 파일 내용 검증을 의미하지 않는다.

### 3.3 매칭 **[확정]**

- `--site DBON`은 추출한 4자리 코드와 대소문자 무시 정확 일치한다.
  RINEX2 파일의 `DBON`과 RINEX3·4 긴 식별자의 앞 4자리 `DBON`이 같다.
- `--site SUW1`처럼 네 번째가 숫자여도 동일하다. `SUW` 3자리로 줄이거나
  `SUW1*` 같은 패턴은 두지 않는다.
- 서로 다른 긴 식별자가 앞 4자리가 같으면 같은 `--site`에 모두 포함된다.
  이는 4자리 정석의 결과이며, 9자리로 한 점만 고르는 CLI는 이번 범위에 없다.
- 여러 site 중 하나라도 일치하면 site 조건을 통과한다.

```text
# DBON 코드에 대응하는 모든 활성 카테고리
rinexclient resend --site DBON --from 2026-09-01 --to 2026-09-03

# 네 번째가 숫자인 관측소
rinexclient resend --site SUW1 --from 2026-09-01 --to 2026-09-03

# 두 관측소의 RINEX2 일 자료
rinexclient resend --site DBON,SONP --category RINEX2_DAILY --from 2026-09-01 --to 2026-09-03
```

## 4. 적용 위치와 책임 [제안]

resend에서는 나열된 파일에 기존 임시 입력 제외 규칙을 적용하고, 관측소를
추출·선별한 뒤 Ledger 등록과 후보 선정을 진행한다. 선택 밖 파일에 대해
이번 대상 처리로 Upsert·해시 백필·전송 상태 변경을 하지 않는다.
단, 명령 시작 시 수행하는 기존 Recover의 범위는 별도 책임이며 site 필터로
자동 축소하지 않는다.

- site를 지정했는데 식별할 수 없는 파일은 제외하고 집계한다. 전체 대상으로
  되돌리는 fallback은 두지 않는다.
- site 생략 시 site 파싱 실패를 새로운 제외 사유로 추가하지 않는다.
- live와 dry-run은 같은 site 매칭을 사용한다. dry-run의 장부 쓰기 금지는 유지한다.
- site를 Ledger 식별키에 추가하거나 `FILENAME_V1` 규칙을 바꾸지 않는다.
- 전체 디렉터리를 나열한 뒤 필터링할 수 있으므로 site 지정이 나열 비용까지
  줄인다고 보장하지 않는다.

향후 DOWNLOAD에서는 원격 파일 목록에 같은 추출·매칭 규칙을 사용하되,
다운로드 후보 선정·Ledger 기록·로컬 경로 결정은 DOWNLOAD 설계가 소유한다.
resend의 게이트 우회나 PUT 재시도 정책을 공통 site 함수에 넣지 않는다.

DOWNLOAD의 복수 선택도 site 목록 안에서는 OR, 다른 선택 조건과는 해당 명령이
정한 조합을 적용한다. 특정 site에서 자료를 찾지 못했을 때 다른 site의 다운로드를
계속할지와 종료 코드는 별도 결정이다. resend의 미발견 종료 정책을 자동 복제하지 않는다.

## 5. 관측 [제안]

- 시작 로그에 정규화한 `sites=`를 남긴다. 생략은 `sites=all`이다.
- 선택된 파일 수, site 불일치 수, site 식별 불가 수를 구분한다.
- 선택 0건은 명시적으로 표시한다. 관측소가 존재하지 않는 경우와 해당 기간에
  파일이 없는 경우를 파일 목록만으로 구분할 수 있다고 주장하지 않는다.
- site별 미발견 안내를 채택하면 요청 site별 발견 여부 또는 수를 기록한다.
  전체 합계나 최종 전송 후보 수로 대신하지 않는다. 이미 완료됐거나 검증에서
  보류된 파일도 “발견했으나 미전송”과 “미발견”을 구분한다.
- resend의 안내·종료 정책과 미결 우선순위는
  [메시지와 종료 코드](../SFTPClient_MESSAGES_AND_EXIT_CODES.md) §5·§6을 따른다.
- 별도 site 전용 로그 파일은 요구하지 않는다. 각 명령의 기존 로그·요약을 사용한다.

## 6. 구현·검증 계획 [제안]

resend 계획에서 공통 추출·매칭과 Ledger 등록 전 필터를 하나의 구현 커밋으로
분리한다. CLI 인자와 로그 배선은 resend 명령 커밋에서 연결한다.
향후 DOWNLOAD 연결은 해당 기능의 구현 계획에서 별도로 다룬다.

검증할 동작:

- 짧은 이름·긴 이름에서 **4자리** 관측소 추출, 압축 확장자와 대소문자 처리.
- 네 번째가 숫자인 코드(`SUW1`) 허용, 9자리 CLI 거부.
- 복수 선택·중복 제거·잘못된 입력 거부.
- 향후 DOWNLOAD에서도 두 site의 원격 자료를 함께 선택하고, 선택 밖 site는
  제외하는지 검증한다. 이는 DOWNLOAD 구현 단계의 검증 범위다.
- site와 category 조건의 교집합, site 생략 시 기존 동작 유지.
- site 지정 시 식별 불가 파일 제외, 임시 파일 제외 계약 유지.
- 선택 밖 파일의 장부 불변과 live/dry-run 선택 일치.
- 선택 0건 및 site 제외 집계의 정확성.

## 7. 구현 전 결정할 사항

`--site` 추가, **4자리 정석**, 9자리 CLI 거부, 네 번째 숫자 허용,
**쉼표로 구분한 복수 site 지원(resend·향후 DOWNLOAD 공통)**은 확정이다.
다음만 제안 상태다.

1. ~~4자리 vs 9자리 CLI~~ — **확정.** CLI는 4자리만. 파일의 9자리는 앞 4자리로만 대조.
2. ~~9자리 정확 일치~~ — **기각.** 정석 입력이 아니다.
3. 복수 site의 쉼표 구분은 **확정** (§1·§3.1). site 생략 시 전체 선택은 §2의 제안이며,
   각 명령의 기본 범위는 별도로 정한다.
4. site 지정 시 식별 불가 파일을 제외·집계할지.
5. ~~선택 0건의 종료 코드~~ — **resend는 확정.** 정상 탐색의 선택 0건은
   exit 0과 사유 표시다. 지정 site 자료 미발견은 exit 1로 정했으나, 겹침
   우선순위를 닫기 전에는 구현하지 않고 exit 0과 `site_matched=`로 남긴다.
   문구와 미결은 [메시지 문서](../SFTPClient_MESSAGES_AND_EXIT_CODES.md) §3·§5·§6.

일반 자동 PUT 실행에 `--site`를 노출할지와 DOWNLOAD의 전체 CLI 형태는
**[미결]**이다. 이번 문서로 자동 실행 범위나 DOWNLOAD 구현 시기를 변경하지 않는다.
