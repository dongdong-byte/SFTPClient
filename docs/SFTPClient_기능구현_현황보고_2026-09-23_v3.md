# 관측자료 자동 전송 프로그램 전체 기능 구현 현황

작성일: 2026년 9월 23일 · 세 번째 보고서  
대상 프로그램: SFTPClient

## 1. 전체 진행 현황

**현재까지 자료 탐색, 전송 대상 판단, 서버 전송, 완료 확인, 누락 자료 재전송, 장애 후 재처리, 자료·전송 기록 관리 기능을 구현했습니다.** 설치 초기 작업, 접속 정보 보호, 실행 결과 보관과 점검 기능도 함께 마련했습니다.

프로그램의 전체 처리 흐름은 다음과 같습니다.

**설정 확인 → 자료 찾기 → 기존 기록과 비교 → 전송 대상 선정 → 서버에 전송 → 도착 확인 → 결과 저장 → 다음 실행에 반영**

이 과정에서 미완성 파일, 수정된 자료, 이미 보낸 자료, 전송 실패, 통신 중단을 구분하여 처리합니다. 기관별로 다른 폴더 구조와 특정 관측소의 자료 요청에도 대응할 수 있도록 했습니다.

아래는 개발 시점에 관계없이 **현재 사용할 수 있는 전체 기능을 업무별로 정리한 현황**입니다. 최근 보강 사항도 해당 기능 안에 포함했습니다.

- **구현 완료:** 현재 코드에 기능이 있고 실제 실행 흐름에 연결되어 있습니다.
- **선택 사용:** 기능은 구현했으며 기관에 맞는 설정을 통해 사용합니다.
- **미구현·미완료:** 추가 개발 또는 환경 적용·시험이 남아 있습니다.

기능 구현 완료와 모든 기관에서의 최신 배포본 검증 완료는 구분합니다. 이번 보고서는 현재 코드 확인을 기준으로 작성했습니다.

## 2. 자료 찾기와 기관별 환경 대응

### 2.1 자료 종류별 전송 설정 — 구현 완료

자료 형식별로 일별 자료와 시간별 자료를 구분하고, 각각 사용할지 여부와 원본 위치·전송 목적지를 설정할 수 있습니다. 현재 세 가지 관측자료 형식에 대해 일별·시간별 자료를 나눠 총 여섯 구분을 지원합니다.

**업무 효과:** 기관에서 실제 사용하는 자료만 선택하여 전송하고, 종류별로 서로 다른 저장 위치에 대응할 수 있습니다. 자료 내용을 다른 형식으로 변환하는 기능은 아닙니다.

### 2.2 날짜에 맞는 자료 위치 자동 계산 — 구현 완료

설정한 연도·월·일 또는 연중 날짜 규칙에 따라 확인할 폴더와 보낼 폴더를 계산합니다. 날짜가 바뀔 때마다 담당자가 폴더 위치를 바꿔 입력할 필요를 줄였습니다.

### 2.3 최근 자료 확인과 넓은 기간 재확인 — 구현 완료

일반 실행에서는 최근 날짜의 자료를 확인하고, 지정한 시각의 실행에서는 더 넓은 기간을 확인합니다. 담당자가 필요할 때 넓은 기간 확인을 직접 실행할 수도 있습니다.

**업무 효과:** 늦게 도착한 자료를 다시 찾을 수 있습니다. 정기 실행 자체는 운영체제의 예약 실행 기능을 이용합니다.

### 2.4 기관마다 다른 하위 폴더 탐색 — 구현 완료

날짜 폴더 아래에 파일이 바로 있거나, 시간별·관측소별 폴더 등으로 여러 단계 나뉘어 있어도 안쪽 폴더까지 따라가 자료를 찾습니다. 날짜 폴더까지의 위치는 설정하며, 다른 위치로 연결되는 항목은 건너뜁니다.

**업무 효과:** 기관마다 하위 폴더 배치가 달라도 같은 프로그램으로 대응할 수 있는 범위를 넓혔습니다.

### 2.5 탐색 오류와 중복 파일 구분 — 구현 완료

없는 폴더와 읽지 못한 폴더를 구분해 기록하고, 다른 폴더의 탐색은 계속합니다. 같은 자료 구분 안에서 같은 이름의 파일을 여러 번 발견하면 중복 후보를 제외하고 기록을 남깁니다.

**업무 효과:** 일부 폴더의 문제를 확인할 근거를 남기고 같은 파일의 중복 선정을 줄입니다. 이름이 같은 여러 파일 중 어느 내용이 최신인지를 자동 비교해 고르는 기능은 아닙니다.

## 3. 전송할 자료 판단과 미완성 자료 제외

### 3.1 새 자료·수정 자료·기존 자료 구분 — 구현 완료

발견한 파일을 저장된 기록과 비교합니다. 처음 들어온 자료, 변경된 자료, 이전과 같은 자료를 구분하고, 해당 자료의 전송 완료 여부까지 확인하여 보낼 대상을 결정합니다.

**업무 효과:** 이미 보낸 자료의 반복 전송을 줄이면서, 같은 이름으로 수정된 자료도 다시 처리할 수 있습니다. 내용이 같더라도 아직 보내지 못한 자료는 전송 대상으로 판단할 수 있습니다.

### 3.2 수정 시각만 바뀐 자료의 불필요한 재전송 억제 — 구현 완료

파일 크기는 같고 수정 시각만 바뀐 경우, 저장한 내용 비교 정보와 현재 내용을 대조합니다. 내용이 같다고 확인되면 새 수정본으로 취급하지 않고 시각 기준만 갱신합니다.

비교 정보가 없거나 읽기에 실패한 경우에는 같은 내용이라고 단정하지 않습니다. 기존 자료에 부족한 비교 정보도 실행 중 정해진 수만큼 보충할 수 있도록 했습니다.

### 3.3 작성 중이거나 비어 있는 자료 제외 — 구현 완료

알려진 임시 이름으로 저장된 파일, 크기가 0인 파일, 수정 직후로 대기 시간이 필요한 파일은 바로 보내지 않습니다. 파일명과 설정한 자료 종류가 명백히 맞지 않는 경우도 제외합니다. 제외한 사유와 건수를 남기고 다음 실행에서 다시 판단합니다.

**업무 효과:** 미완성 자료나 잘못 섞인 자료가 정상 자료처럼 전달되는 위험을 줄입니다. 관측값 자체의 정확성을 검사하는 기능과는 구분됩니다.

### 3.4 필요한 자료 묶음이 갖춰졌는지 확인 — 구현 완료·선택 사용

함께 필요한 자료 종류를 지정하면, 확인 가능한 묶음에 필요한 자료가 갖춰졌을 때 전송을 시작합니다. 미완성 묶음은 보류하고 부족한 종류를 기록합니다. 한 번의 처리량을 제한할 때도 대상 묶음이 쪼개지지 않도록 조정합니다.

기본 설정은 사용하지 않는 상태입니다. 묶음을 판별할 수 없는 이름은 안내를 남기고 개별 파일로 처리합니다. 전송 도중 실패했을 때 이미 보낸 묶음 전체를 되돌리는 기능은 포함하지 않습니다.

## 4. 서버 전송과 도착 확인

### 4.1 지정 서버로 실제 파일 전송 — 구현 완료

설정한 서버에 접속해 선택된 자료를 지정 위치로 보냅니다. 받는 쪽에 필요한 폴더가 없으면 생성하고, 파일은 원래 이름과 내용으로 전달합니다.

### 4.2 전송 직전 원본 재확인 — 구현 완료

자료를 찾은 뒤 실제 전송하기 전까지 파일이 없어졌거나 크기가 바뀌었는지 다시 확인합니다. 달라진 파일을 이전 판단 그대로 보내지 않고 해당 실행에서 제외합니다.

**업무 효과:** 자료 탐색과 실제 전송 사이에 원본 상태가 바뀌는 상황에 대응합니다.

### 4.3 전송 중인 파일과 완료 파일 구분 — 구현 완료

서버에 보내는 동안에는 임시 이름을 사용합니다. 전송 후 크기를 확인하고 정식 이름으로 바꾼 뒤, 최종 파일의 크기를 다시 확인해야 완료로 기록합니다. 기존 파일을 바꿀 수 있는 서버 기능도 접속 단계에서 확인합니다.

**업무 효과:** 전송이 끝나지 않은 파일을 완료 파일로 취급할 위험을 줄입니다. 도착 확인은 파일 존재와 크기 기준이며, 서버의 파일 내용 전체를 다시 읽어 원본과 대조하는 방식은 아닙니다.

### 4.4 여러 작업 동시 처리와 처리량 조절 — 구현 완료

폴더별 전송 작업을 나누어 설정한 개수까지 함께 처리합니다. 한 번에 보낼 파일 수를 제한할 수 있으며, 날짜가 오래된 후보부터 선정합니다. 제한 때문에 제외된 자료는 다음 실행에서 다시 판단합니다.

**업무 효과:** 자료가 한꺼번에 쌓였을 때 동시 작업 수와 회차별 처리량을 운영환경에 맞춰 조절할 수 있습니다. 실제 속도 개선 정도는 회선과 서버 환경에 따라 달라집니다.

## 5. 누락 자료 재전송과 관측소 선택

### 5.1 과거 자료 자동 재확인·전송 — 구현 완료

일반 전송을 먼저 처리한 뒤, 더 오래된 기간에서 새로 들어왔거나 변경됐거나 아직 보내지 못한 자료를 추가로 찾아 보냅니다. 운영 시작일과 기록 보존기간을 고려해 범위를 제한하고, 일반 전송에서 남은 처리 여유를 사용합니다.

일반 전송이 모두 실패했거나 통신이 멈춘 경우에는 후속 작업을 보류합니다. 이미 완료된 파일을 무조건 다시 보내는 기능은 아닙니다.

### 5.2 담당자가 기간·자료 종류를 지정하는 재전송 — 구현 완료

시작일과 종료일, 처리할 자료 종류를 지정해 재전송을 실행할 수 있습니다. 요청 날짜가 허용 범위를 벗어나면 실행 전에 알립니다. 실제 전송 전 대상 확인도 가능하며, 자동 재시도 횟수를 모두 사용한 자료에는 수동으로 추가 시도 기회를 줄 수 있습니다.

**업무 효과:** 특정 기간의 장애 복구나 자료 요청에 대해 범위를 지정하여 대응할 수 있습니다. 재전송 시 필요한 자료 묶음 조건도 별도로 설정할 수 있습니다.

### 5.3 한 곳 또는 여러 관측소 선택 — 구현 완료

재전송할 때 관측소 한 곳 또는 여러 곳을 선택할 수 있습니다. 날짜·자료 종류 조건을 함께 적용하므로 “두 관측소의 특정 기간 일별 자료”처럼 대상을 좁힐 수 있습니다.

대소문자와 중복 입력을 정리하고, 잘못된 코드 입력을 확인합니다. 파일 이름에서 관측소를 구분하며 요청한 관측소별 발견 건수도 기록합니다.

**현재 적용 범위는 재전송입니다.** 앞으로 개발할 자료 모으기 기능에도 관측소 선택 요구를 반영할 예정입니다.

## 6. 장애 대응과 작업 겹침 방지

### 6.1 실패 기록과 재시도 횟수 관리 — 구현 완료

전송 실패 사유와 누적 시도 횟수를 저장합니다. 다음 실행에서 파일이 대상 범위 안에 있고 남은 시도 횟수가 있으면 다시 처리합니다. 반복 실패 파일을 무한정 시도하지 않도록 했습니다.

### 6.2 프로그램 중단 후 처리 상태 정리 — 구현 완료

다음 실제 전송 실행을 시작할 때, 이전 실행에서 진행 중으로 남은 자료를 찾아 확인합니다. 이 프로그램이 전송 중 만들었던 임시 파일을 정리하고 실패 상태로 바꿔, 재시도 조건에 따라 다시 처리할 수 있게 합니다.

**업무 효과:** 강제 종료 등의 이유로 중간 상태에 남은 자료를 다음 작업으로 연결할 수 있습니다. 파일 중간부터 이어 보내는 방식은 아니며, 원격 통신 오류가 계속되면 정리 자체도 실패할 수 있습니다.

### 6.3 통신 정지 감지와 취소 처리 — 구현 완료·현장 확인 필요

진행 중인 서버 작업에 일정 시간 진전이 없으면 새로운 전송 착수를 중단하고 연결을 닫습니다. 실패 기록을 남기는 처리를 거치며, 사용자 중단 요청에도 취소 처리가 연결되어 있습니다.

**업무 효과:** 응답 없는 통신을 계속 기다리는 상황에 대응합니다. 실제 기관 환경에서의 통신 단절·회복 시험은 추가 확인이 필요하며, 모든 종류의 저장장치 지연까지 해결하는 기능은 아닙니다.

### 6.4 동일 작업의 중복 실행 방지 — 구현 완료

같은 전송 기록을 사용하는 작업이 동시에 진행되지 않도록 제어합니다. 정기 작업이 겹치면 추가 실행을 종료하고, 수동 재전송은 정해진 시간까지 기다립니다. 비정상 종료로 남은 실행 흔적은 경과 시간 기준으로 처리합니다.

실제 가장 오래 걸리는 작업에 맞춰 제한 시간을 설정해야 합니다.

## 7. 자료·전송 기록 저장과 자동 관리

**프로그램 안에 자료 관리대장을 만들어, 파일의 현재 정보와 변경 차수별 전송 결과를 저장하도록 했습니다.** 이 기록을 다음 실행에서 다시 읽어 중복 전송, 수정본 누락, 실패 자료 처리를 판단합니다. 단순한 실행 메시지 보관과 별도의 기능입니다.

### 7.1 자료별 기본 정보 등록 — 구현 완료

기본 검사를 통과한 자료에 대해 다음 정보를 저장합니다.

- 자료 이름과 종류
- 파일 크기와 변경 판단에 사용하는 시각
- 최초 발견 시점과 기본 검사를 통과한 시점
- 현재 변경 차수
- 함께 묶이는 자료와 자료 종류 정보
- 확보된 내용 비교 정보

자료 종류와 파일 이름을 함께 구분하므로, 이름이 같더라도 서로 다른 종류의 자료 기록이 섞이지 않도록 했습니다.

### 7.2 변경 차수 자동 부여와 이전 전송 결과 구분 — 구현 완료

처음 발견한 자료는 첫 번째 차수로 등록합니다. 같은 이름의 자료가 변경된 것으로 판단되면 차수를 자동으로 올립니다. 전송 결과는 해당 차수와 연결하여 저장하므로, 이전 차수의 완료 기록과 현재 수정본의 처리 상태를 구분할 수 있습니다.

예를 들어 **처음 보낸 자료는 완료로 남겨 두고, 나중에 수정된 자료는 새 차수의 전송 대상으로 관리**합니다. 수정 시각만 바뀌고 내용이 같다고 확인된 경우에는 차수를 올리지 않습니다.

모든 과거 파일의 실제 내용을 복사해 보관하는 기능은 아닙니다. 같은 차수의 재시도마다 별도 이력 줄을 계속 추가하는 방식도 아니며, 해당 차수의 상태·누적 시도 횟수·실패 정보를 갱신합니다.

### 7.3 전송 단계와 결과 저장 — 구현 완료

자료의 변경 차수별로 **전송 대기·진행 중·완료·실패**를 구분합니다. 함께 저장하는 정보는 다음과 같습니다.

- 누적 전송 시도 횟수
- 전송한 원본 크기와 도착 확인에 사용한 크기
- 서버의 저장 위치와 전송 중 임시 위치
- 정식 파일로 전환한 시점과 최종 확인 시점
- 실패 사유

**업무 효과:** 자료를 발견한 사실과 실제 전송을 마친 사실을 분리해서 관리하고, 실패·중단 자료를 다음 실행에서 판단할 근거를 확보했습니다.

### 7.4 중복 착수와 잘못된 기록 변경 방지 — 구현 완료

이미 완료했거나 다른 작업이 처리 중인 자료를 다시 착수하지 않도록 기록 상태를 확인합니다. 상태 변경은 허용된 순서에서만 적용하고, 예상한 기록과 달라졌다면 이를 확인하도록 했습니다. 같은 자료의 중복 등록과 잘못된 값 저장을 막는 검사도 넣었습니다.

**업무 효과:** 여러 파일을 함께 처리하더라도 전송 판단에 사용하는 기록이 서로 어긋날 위험을 줄였습니다.

### 7.5 프로그램 개선 시 기록 형식 자동 갱신 — 구현 완료

시작할 때 기록 보관 형식의 버전을 확인합니다. 지원하는 이전 형식이면 기존 자료·전송 이력을 유지하면서 새 기능에 필요한 기록 항목을 순서대로 추가하고, 적용된 버전과 변경 결과를 남깁니다.

변경 중 실패하면 해당 단계의 일부만 반영되지 않도록 처리합니다. 지원하지 않는 형식은 임의로 변경하지 않고 오류를 알립니다.

**업무 효과:** 기능을 추가할 때 기존 기록을 지우고 다시 시작하는 부담과 설치 현장의 수작업을 줄였습니다.

### 7.6 운영 시작일 관리와 과거 확인 범위 제한 — 구현 완료

기존 기록을 바탕으로 운영 시작일을 관리하고, 이를 과거 자료 자동 재확인의 범위에 반영합니다. 최초 설치나 사전 점검 때문에 지나치게 오래된 기간이 자동 처리 대상으로 잡히는 것을 줄이도록 했습니다.

### 7.7 오래된 전송 이력 자동 정리 — 미구현

보존기간 설정과 범위 검사는 있지만, 기간이 지난 관리대장 기록을 실제로 삭제하는 처리는 아직 없습니다. 현재 기준은 30일이며, 정리 후 남아 있는 원본 파일이 새 자료로 오인되어 다시 전송되지 않는지까지 확인해야 합니다.

이는 아래의 **실행 기록 파일 자동 정리와 다른 기능**입니다. 관리대장 전체가 미구현인 것이 아니라, 보존기간에 따른 정리 작업이 남아 있는 상태입니다.

## 8. 설치·보안·점검과 실행 결과 확인

### 8.1 최초 설치 시 기존 전송분 반영 — 구현 완료

서버에 이미 있는 자료와 원본의 크기를 대조해 일치하는 자료를 전송 완료 기록에 반영할 수 있습니다. 새 프로그램 설치 직후 기존 자료를 대량으로 다시 보내는 상황을 줄이기 위한 기능입니다. 내용 전체가 동일하다는 검사는 아니므로, 기존 전송분을 신뢰한다는 전제에서 사용합니다.

### 8.2 설정 자동 읽기와 실행 전 검사 — 구현 완료

프로그램 옆의 설정 파일을 기본으로 읽고, 설정 위치를 기준으로 관련 파일을 찾습니다. 자료 경로, 접속 정보, 실행 범위와 처리량 등의 설정을 검사하고 필요한 파일의 존재도 확인합니다.

**업무 효과:** 예약 실행 시 시작 위치가 달라 생기는 경로 문제와 잘못된 설정으로 인한 조용한 미처리를 줄입니다.

### 8.3 접속 정보 보호와 상대 서버 확인 — 구현 완료

**윈도우에서 제공하는 정보 보호 기능(DPAPI)을 사용해, 서버 주소·접속 아이디·접속 포트 번호를 평문 대신 암호화된 값으로 설정 파일에 저장하고 사용하는 기능을 구현했습니다.** 설정 파일을 열었을 때 실제 접속 정보가 그대로 드러나는 것을 줄이기 위한 조치입니다.

암호화된 값을 만드는 보조 실행 기능과, 실행 시 해당 값을 복원해 접속에 사용하는 처리도 함께 구현했습니다. 서버 접속 시에는 인증 파일을 사용하고 등록된 상대 서버인지 확인합니다.

리눅스에 동일한 설정값 보호 기능을 구현한 상태는 아닙니다.

### 8.4 실제 전송 전 대상 확인과 시험용 파일 전송 — 구현 완료

실제로 보내지 않고 대상 자료와 제외 사유를 확인하는 미리보기를 제공합니다. 미리보기에서는 대상 선정에 따른 자료·전송 상태를 등록하거나 바꾸지 않습니다. 다만 프로그램 시작 시의 기록 형식 확인·자동 갱신 등은 별개로 수행될 수 있습니다.

또한 외부 서버 대신 지정한 저장 위치에 파일을 복사하여 전송 흐름을 점검하는 방식도 구현했습니다. 이 방식의 시험 결과와 실제 기관 서버 연결 확인은 구분합니다.

### 8.5 날짜별 실행 기록 보관·정리 — 구현 완료

실행 내용을 화면과 날짜별 파일에 함께 남기고, 날짜가 바뀌면 새 파일로 기록합니다. 정해진 보존기간이 지난 실행 기록 파일을 정리합니다. 기록 저장 문제는 경고하고 전송은 계속하도록 했습니다.

### 8.6 처리 결과와 제외 사유 요약 — 구현 완료

자료 종류별로 탐색·신규·변경·제외·전송 후보와 처리 시간을 정리하고, 전송 단계의 시도·완료·실패 결과도 남깁니다. 내용이 같아 변경 처리를 줄인 건수와 비율, 확인 범위, 관측소 선택 결과 등을 통해 실행 내용을 확인할 수 있습니다.

**업무 효과:** “실행됐다”는 사실뿐 아니라 어떤 자료를 처리했고 어떤 이유로 제외했는지 추적할 근거를 마련했습니다. 별도의 통계 화면이나 외부 알림 발송 기능을 뜻하지는 않습니다.

## 9. 앞으로 완료해야 할 작업

### 우선 작업: 오래된 전송 이력 자동 정리 — 미구현

7.7의 관리대장 정리를 구현하고, 정리 전후의 자료 판단이 올바른지 확인해야 합니다.

### 리눅스 환경 적용·시험 — 미완료

리눅스용 실행파일 준비, 실제 자료 위치 설정, 예약 실행, 서버 연결과 전체 처리 과정을 확인해야 합니다. 현재 기능 구현과 별도로 환경 적용이 남아 있습니다.

### 기존 자료를 정해진 폴더로 모으기 — 미구현

기관마다 다른 위치에 있는 자료를 찾아 파일명에 적힌 관측 날짜에 맞춰 표준 폴더로 복사하는 기능입니다. 관측소 선택, 복사 완료 확인, 처리 기록 저장을 연결하고 이후 기존 전송 기능이 이 자료를 보내도록 할 예정입니다.

현재 완료한 하위 폴더 탐색은 **자료를 찾는 기능**이고, 이 항목은 **자료를 새 위치에 모으는 기능**입니다. 현재 프로그램에서는 이 수집 작업을 실행할 수 없습니다.

### 실제 운영환경 최종 확인 — 기능별 추가 확인 필요

기관별 실제 폴더에서의 자료 발견, 최신 설정 적용, 통신 장애 후 종료·재실행, 기존 기록 유지, 처리 시간과 실행 기록 보관을 확인해야 합니다. 특히 통신 정지 대응을 실제 회선에서 검증한 것으로 확대해 보고하지 않습니다.

### 후속 단계 또는 별도 요구 시 검토

- 다른 서버에 접속해 자료를 내려받는 기능과 수신·송신 통합은 후속 단계입니다.
- 미완성 자료 묶음의 별도 보고서 발송은 이번 범위에서 제외했습니다.
- 리눅스 전용 추가 보안 기능은 공식 점검에서 구체적인 요구가 나올 때 별도로 검토합니다.
