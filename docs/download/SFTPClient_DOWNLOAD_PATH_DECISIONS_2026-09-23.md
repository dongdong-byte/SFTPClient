## 2. 정정: 09-20 "DOWNLOAD = 로컬 수신" 정의

### 2.1 이전 정의 (지침 상단 · MVP2 6번 · 1145줄 · PATH v3 머리말)

> 기관마다 제각각인 로컬 저장 경로의 파일을 표준 폴더로 복제하고, PUT은 표준 폴더를 보낸다.

### 2.2 정정 사유

- [자료] 대표가 참고하라고 한 `backup_RNX*.py`는 **원격 SFTP 서버에 접속해 파일을 내려받는**
  스크립트다. 로컬 복제가 아니다.
- [자료] 경로 범용화(PATH v3, 재귀 탐색)가 완료되어 PUT이 제각각인 로컬 경로를 직접 읽는다.
  로컬 수신의 원래 필요(PUT이 복잡한 경로를 못 읽음)가 해소됐다.
- [지시] 올인원은 "한 흐름으로 이어지는 파이프라인"이 아니라 **기능 모음**이다.
  DOWNLOAD → PUT을 한 세트로 묶지 않는다.

### 2.3 새 정의

| 항목 | 내용 |
|---|---|
| DOWNLOAD | **원격 SFTP → 로컬 GET.** PUT과 독립된 기능 |
| 기본 상태 | 꺼짐 (`Mode=put` 기본). 필요한 기관만 켠다 |
| 사용처 | 측위원(중계 서버 구조). 중계 서버가 있고 그 서버에 설치할 수 없는 기관 |
| BOTH | 한 실행 안에서 DOWNLOAD 다음 PUT을 순서대로 돌리는 것뿐. 둘 사이에 계약(표준 폴더)은 없다 |
| 폐기 | "표준 폴더", "PUT은 표준 폴더를 보낸다", "로컬 수신" 표현 |

### 2.4 구조별 필요 여부

| 구조 | DOWNLOAD |
|---|---|
| 단일 서버 (대부분 기관) | 불필요. PUT만 사용 |
| 중간 서버 + 우리 프로그램 설치 가능 | 불필요. PUT 두 번 |
| 중간 서버 + 설치 불가 (측위원) | **필요** |

## 3. 참고 자료 분석 요약

### 3.1 `backup_RNXDaily.py` / `backup_RNXHourly.py` (GET)

| 동작 | 내용 |
|---|---|
| 입력 | 날짜 1개 (`YYYY/MM/DD`). **site 인자는 없다** |
| 원격 경로 | `{version}/{year}/{doy}/` (Hourly는 그 아래 `00`~`23`) |
| 분류 | 파일명 앞 4자(`file[:4]`)를 관측소로 보고 로컬 폴더를 만든다 |
| 로컬 경로 | Daily `base\SITE\RINEX_Day\` / Hourly `base\YYYY\DOY\SITE\` (시간 폴더는 평평하게) |
| 중복 | 로컬에 같은 이름이 있으면 건너뜀 |

→ site는 **분류(목적지 폴더)**에만 쓰인다. 선택(필터)은 없다.

### 3.2 sendRinex (`Send_RINEX_SFTP.ps1`, PUT)

| 동작 | 내용 |
|---|---|
| 관측소 | 고정 목록 32개. `<STATION>*.gz` 앞부분 일치로 선택 |
| 쌍 | 기준국·감시국 쌍을 목록에 넣을 뿐. **두 관측소가 모두 있을 때만 보내는 로직은 없다** |
| 경로 | `E:\RINEX-V2-H\yyyy\doy\HH` → `/RINEX2Outgoing/RNX2_H/yyyy/doy/HH/` (하위 폴더 복제) |
| 범위 | UTC 기준 7일, 매시 :10, 매번 전부 덮어쓰기 |
| 원격 정리 | 30일 지난 DOY 폴더 삭제. 전송 실패 시 생략, 30일 미만·3660일 초과·얕은 경로 거부 |

→ site의 두 역할이 모두 필요하다: **선택**(측위원 요구, `Sites`)과 **분류**(목적지 `(SITE)`).

## 4. 경로: 토큰 목록 방식 (PATH v4 방향)

### 4.1 방식 선택

| | A. 토큰 목록 방식 **[판단: 채택]** | B. 사용자 정의 방식 (기각) |
|---|---|---|
| 형태 | 프로그램이 제공하는 토큰을 ini에서 배치 | ini에 정규식 등으로 토큰을 직접 정의 |
| 값 추출 | 코드 (RINEX 표준 파서) | 현장 설정 |
| 설정 오류 | 시작 단계에서 거부 가능 | 실행해 봐야 드러남 (조용한 오분류) |

RINEX 파일명은 표준이라 뽑을 수 있는 필드가 한정돼 있다. 목록으로 충분하다.

### 4.2 토큰 분류 (값의 출처 기준)

| 종류 | 토큰 | 값의 출처 |
|---|---|---|
| 날짜 | `(YYYY)` `(YY)` `(DOY)` `(MM)` `(DD)` | 스캔 날짜 (기존) |
| 파일명 | `(SITE)` `(HH)` … (후보: `(TYPE)` `(CCC)` 등) | 파일별 추출 |
| 고정값 | [미결] 필요 시 | ini |

### 4.3 규칙

| # | 규칙 | 출처 |
|---|---|---|
| 1 | 토큰은 PUT·GET, 원본·목적지 **어디에나** 배치할 수 있다. 위치·순서 자유 (`(YYYY)\(SITE)\(DOY)` 가능) | [지시] |
| 2 | 원본 경로의 파일명 토큰 → 그 위치의 폴더를 나열. 단 `(SITE)`는 `Sites` 지정 시 해당 관측소만 찾아감 | [판단] |
| 3 | 목적지 경로의 파일명 토큰 → 파일별 추출값으로 채움 | [판단] |
| 4 | 카테고리가 추출할 수 없는 토큰(예: RINEX2 경로의 국가코드)은 **시작 단계에서 거부** | [판단] |
| 5 | 개별 파일 추출 실패 → 제외하고 집계 (resend 식별 불가 정책과 동일) | [판단] |
| 6 | `(HH)`는 목록에 두되 강제하지 않음. 필요한 현장만 목적지에 기재 | [지시] |
| 7 | 처음 제공 토큰은 최소 (`(SITE)`, `(HH)`). 구조는 범용, 토큰은 필요할 때 한 줄씩 추가 | [판단] |
| 8 | 토큰을 쓰지 않은 기존 설정은 **동작이 전혀 바뀌지 않는다** | [판단] |
| 9 | 토큰은 폴더 이름 중간·붙여 쓰기 허용 (기존 `(MM)(DD)` 동작 유지). 원본에서 파일명 토큰은 [미결] 폴더 이름 전체 단위로 제한할지 | [판단]/[미결] |

### 4.4 하위 폴더 복제

- 옵션으로 둔다. **기본값은 현재처럼 평평하게 쌓는다.** [지시: 강제하지 않음]
- 켜면 원본 날짜 폴더 아래 상대 경로를 해석 없이 목적지에 그대로 옮긴다.
- 근거: [자료] sendRinex는 복제, backup_RNX Hourly는 평평하게. 두 방식 모두 현장에 있다.

### 4.5 확인된 현재 지원 범위 [자료: 코드 확인]

| 항목 | 현재 |
|---|---|
| 토큰 붙여 쓰기·폴더 이름 중간 (`(MM)(DD)` → `0829`) | 지원 (`pathpl.Parse`) |
| DOY 없는 경로 (우주환경센터 `/occ/data/gps/temp/(YYYY)/(MM)(DD)/`) | 지원 |
| `SWIC241h.18o` 판정 | RINEX2 Hourly로 정상 판정 |
| 평평한 목적지 (`/RNX/`) | 지원 |
| `(SITE)` 등 파일명 토큰 | **미지원 → PATH v4** |
| 하위 폴더 복제 | **미지원 (현재 목적지는 `RemotePath.Expand(When)`로 평평) → PATH v4** |

## 6. 안전 조건 [판단]

| # | 위험 | 조건 |
|---|---|---|
| 1 | DOWNLOAD 목적지 ⊂ PUT 원본 → 받은 파일 재전송 | `RepostDownloaded=true` 명시 없으면 **시작 거부**. 측위원(의도된 중계)은 명시 |
| 2 | PUT 목적지 = DOWNLOAD 원본 → 올린 파일 다시 수신 (순환) | **무조건 거부** |
| 3 | PUT·DOWNLOAD가 다른 장부 사용 → `origin=DOWNLOAD` 방어 무력화 | 한 PC에서는 장부 하나 |
| 4 | 같은 장부로 동시 실행 | 기존 장부 잠금으로 직렬화. 잠금 보유 모드를 로그에 남김 |
| 5 | 공통 부품 변경으로 운영 중인 PUT 회귀 | 토큰 없는 설정은 기존 코드 경로 그대로. 기존 PUT 테스트 전부 통과가 조건 |

경로 겹침 판정: [미결] 첫 토큰 앞 고정 부분 비교(보수적 판정) 등 PATH v4에서 확정.

## 7. 측위원 목표 구성 (예시)

```
[중계 서버] ──GET(Sites 선택)──▶ [측위원 PC: 로컬 경로에 (SITE) 배치] ──PUT──▶ [지리원 RNX 폴더 (평평)]
```

- Mode = both, `RepostDownloaded = true`
- 지리원 쪽 RemotePath는 토큰 없는 평평한 경로 (현재도 지원)

## 9. 대표 확인이 필요 없는 항목 (개발 판단으로 확정)

대표 지시는 "돌아가기만 하면 된다"이므로, 아래 세부는 개발 판단으로 기본값을 정하고
**대표에게 따로 묻지 않는다.** 운영 중 문제가 생기면 설정으로 조정한다.

- 토큰 목록 방식(A) 채택, 사용자 정규식 방식 기각
- 처음 제공 토큰 최소화 (`(SITE)`, `(HH)`)
- 추출 불가 토큰 시작 거부, 파일별 추출 실패 제외·집계
- 하위 폴더 복제 기본값 = 평평하게
- 안전 조건 1~5
- `Sites` 매칭 규칙 (기존 resend 규칙 재사용)
