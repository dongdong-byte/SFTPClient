# DOWNLOAD 로그 화면·파일 분리 합의 기록

- 날짜: 2026-09-26
- 적용 범위: DOWNLOAD 보고와 파일별 로그
- 성격: 구현을 명령하는 규칙이 아니라, 현재 판단과 근거 및 미확인 사항의 기록

## 배경

SFTPClient는 국가기관 서버에서 실행되고 기관 담당자가 실행 화면을 본다. 기존
로거는 `io.MultiWriter(os.Stderr, logWriter)`를 사용해 모든 줄을 화면과 파일에
동시에 남겼다. DOWNLOAD의 원격 나열 관찰 중에는 기관의 폴더 구조에서 생기며
개발자나 현장 담당자가 고칠 수 없는 것도 있다. 이런 줄을 매회 화면 경고로
보내면 실제 조치 신호가 묻힐 수 있다.

## 기준

- 현장에서 조치할 수 있거나 설정 오류 가능성이 큰 항목은 화면과 파일에 남긴다.
- 기관의 원격 구조에서 생기며 우리 쪽에서 고칠 수 없는 관찰은 파일에만 남긴다.
- 로그 파일에는 모든 줄이 남아야 한다.
- 파일 전용 로거를 사용할 수 없으면 줄을 버리지 않고 화면 로거로 보낸다.

## 현재 분류

| 항목 | 판단 | 화면 | 파일 |
|---|---|:---:|:---:|
| 회차 요약 (`종류=… 수신=… 소요=…`) | 실행 결과 | O | O |
| `나열실패` | 권한·회선 등으로 요청 범위를 완전히 확인하지 못함 | O | O |
| `원격폴더없음` | 범위 전체에서 폴더가 없으면 `RemotePath` 오기 가능 | O | O |
| `패턴폴더없음` | `(SITE)`·`(HH)` 패턴에 맞는 폴더가 하나도 없어 설정 오류 가능 | O | O |
| `비정규항목` | 링크 등 원격 구조의 관찰 | X | O |
| 일부 `폴더불일치` | 맞는 폴더도 존재하는 상태의 원격 구조 잡음 | X | O |
| 일부 `폴더밖파일` | 맞는 패턴 루트도 존재하는 상태의 원격 구조 잡음 | X | O |
| `목적지중복` 건수 | 회차 요약의 집계 필드 | O | O |
| `목적지중복` 상세 경로 | 원격 여러 경로가 같은 로컬 목적지로 수렴 | X | O |
| `종류미상` 요약 | 수신은 했지만 이름으로 종류를 확정하지 못함 | O | O |
| `종류미상` 파일 경로 | 원격 파일의 상세 | X | O |
| `실패`, `충돌`, `비정상대상`, `임시파일정리실패` | 로컬 조치 대상 | O | O |

기관 구조 관찰은 오류로 단정하지 않으므로 `나열경고`가 아니라 `나열참고`로
표시한다. 단, 패턴 폴더가 하나도 맞지 않으면 DOWNLOAD가 영구히 대상 없음으로
끝날 수 있으므로 `패턴폴더없음` 화면 경고로 승격한다. 일부 폴더만 규칙 밖이면
파일 전용 참고로 유지한다.

## 구현 형태

- `Report.Print(console, detail *log.Logger)`는 요약·나열경고를 `console`,
  나열참고를 `detail`로 보낸다.
- `download.Options.DetailLogger`는 `목적지중복`과 `종류미상` 상세 경로를
  보낸다. 나머지 파일별 로그는 `Options.Logger`로 보낸다.
- `목적지중복` 건수는 다른 사유 집계처럼 회차 요약에 남으므로 화면에도
  보인다. 화면에서 숨기는 것은 개별 원격·로컬 경로뿐이다.
- `detail` 또는 `DetailLogger`가 nil이면 각각 `console` 또는 `Logger`로
  대체한다. 로그를 버리는 경로는 두지 않는다.
- PUT의 `RunReport.Print`와 PUT 로그 형식은 변경하지 않는다.

## 종료 판단

원격 나열 실패(`Scan.Errs > 0`)는 후보가 0이어도 정상적인 대상 없음이 아니다.
요청 범위를 완전히 확인하지 못했으므로 `Report.Failed()`에 파일 수신 실패와
함께 포함한다. 커밋 7의 main은 이 값이 1 이상이면 부분 실패 종료 코드를 써야
한다. 화면 요약의 `실패=`는 파일 실패만 표시하고, 나열 실패는 별도의
`나열경고 … 나열실패=`로 표시해 원인을 구분한다.

`원격폴더없음`과 `패턴폴더없음`은 현재 경고만 남기며 그 자체로 실패 종료에
포함하지 않는다. 실제 기관 로그에서 정상적인 무자료 상태와 설정 오류를 구분할
근거를 얻은 뒤 재검토할 수 있다.

## 판단이 들어간 곳

- `원격폴더없음`은 범위 전체에서 폴더를 하나도 찾지 못했을 때(`Dirs == 0`)
  만 낸다. Hot 범위에서 오늘 날짜 폴더 하나가 아직 없는 것은 경고하지 않는다.
- `폴더불일치`·`폴더밖파일`은 일부 정상 패턴 루트가 있으면 건수만 파일에
  남긴다. 무해한 백업 폴더가 흔하다는 가정이며 실제 기관 구조는 미확인이다.
- `충돌`은 로컬에 크기가 다른 최종 파일이 있어 현장 조치 대상으로 본다.
  원격 원본 재생성으로 크기가 바뀐 경우에는 원인이 원격일 수도 있다.
- `종류미상`은 파일을 거부하지 않고 수신한다. 새로 수신한 회차에만 요약으로
  드러내며, 이미 존재하는 파일을 매회 반복 경고하지 않는다.

## 커밋 7 및 현장 확인 사항

- main에서 파일 전용 로거를 실제 배선한다. 예정 형태는
  `detail := log.New(logWriter, "", log.LstdFlags)`이다.
- 로그 파일을 열지 못하면 파일 전용 줄을 화면으로 보내 기록 유실을 막는다.
  고객 화면에 참고 줄이 나타나는 부작용은 감수할지 커밋 7에서 최종 확인한다.
- 한국어가 Windows 콘솔, 작업 스케줄러 로그 파일, Oracle Linux 9.4에서
  깨지지 않는지는 실제 설치 환경에서 확인한다.
